# CareFirst — Codebase Index

Healthcare platform (Pakistan, PKR) connecting patients, doctors, labs, lawyers and an admin. Core idea: lab tests paid in **installments**, with a 3-step receipt verification flow and automatic **legal escalation** of defaulters. Also a **community support** (charity) track for needy patients.

Two independent apps in one git repo (GitHub: `makki-Q/carefirst`, branch `main`), no automated test suite in the repo, no monorepo tooling:

| Dir | Stack | Run |
|---|---|---|
| `carefirst-backend/` | Node (CommonJS), Express 4, Mongoose 7, Socket.IO 4, multer, node-cron, JWT | `npm run dev` (nodemon) → :5000 |
| `carefirst-web-modified/` | React 19, Vite 8, Tailwind 4 (auth pages only), mix of `.jsx` and `.tsx` | `npm run dev` → :5173, proxies `/api` and `/socket.io` to :5000 |

Env (`carefirst-backend/.env.example`): `PORT, MONGO_URI, JWT_SECRET, JWT_EXPIRES_IN, ADMIN_USERNAME, ADMIN_PASSWORD, CLIENT_URL, BASE_URL`; report reading (`AZURE_DOCINTEL_ENDPOINT/KEY`); installment settings (`SERVICE_FEE_PKR`, `DOWN_PAYMENT_PERCENT`, `CAREFIRST_*`); True Cost (`TRAVEL_RATE_MOTORBIKE/CAR/RIDE`, `OSRM_URL`); Azure (`AZURE_TRANSLATOR_KEY/REGION`, `AZURE_SPEECH_KEY/REGION`, optional `AZURE_*_ENDPOINT`, `AUDIO_CACHE_DIR`). The real Azure keys live only in the local `.env` (gitignored) — never commit them.
Project lives at `C:\dev\carefirst` (Windows). Do **not** work in the old OneDrive copy (`OneDrive\Desktop\carefirst2`) — it is obsolete, and OneDrive placeholders made Node fail with `UNKNOWN: unknown error, read`.
In Git Bash, `node`/`npm` are not on PATH — use `"/c/Program Files/nodejs/node.exe"` or `export PATH="/c/Program Files/nodejs:$PATH"`. MongoDB runs locally on `localhost:27017` (dev database `carefirst`).

## Backend (`carefirst-backend/`)

- `server.js` — wires middleware, routes, Socket.IO, 404 handler; on DB connect starts the cron job. Serves `uploads/` statically.
- `config/installments.js` — Step 2 settings from `.env`: `SERVICE_FEE` (`SERVICE_FEE_PKR`, default 500), `DOWN_PAYMENT_PERCENT` (default 20), `CAREFIRST_ACCOUNT` (`CAREFIRST_BANK_NAME/ACCOUNT_TITLE/ACCOUNT_NUMBER/JAZZCASH/EASYPAISA`), plus constants `MAX_OPEN_PLANS` 2, `GRACE_DAYS` 3, `REMINDER_DAYS` [3, 1].
- `config/db.js` — Mongo connect + seeds one `admin` user if none exists.
- `middleware/auth.js` — `protect` (Bearer JWT → `req.user`), `requireRole(...roles)`, `requireActive` (status must be `active`). Routers use a `guard = [protect, requireRole(x), requireActive]` array.
- `middleware/upload.js` — multer disk storage into `uploads/{reports,receipts,community-docs}`; pdf/jpg/png, 10 MB.
- `socket/notificationSocket.js` — clients emit `join(userId)` to enter a room; server emits `notification:new`. `sendNotification(userId, doc)` is called from controllers/job. Room join is not authenticated.
- `jobs/defaulterJob.js` — daily 00:05 Asia/Karachi. Pending installments past due + 3 grace days with no receipt → `overdue`; first time escalates wallet to `defaulter`, creates `DefaulterCase` with generated legal text (`utils/legalAgreementTemplate.js`), assigns the active lawyer with fewest active cases, notifies lawyer/admins/patient. Then `runDueReminders()`: `installment_due_soon` notifications 3 and 1 Pakistan calendar days before each due date (skipped once a receipt is uploaded; sent days stored in `installments[].remindersSent`). Both only look at `active` wallets.
- `utils/installmentPlan.js` — `OPEN_PLAN_STATUSES`, `hasPaymentDetails(labProfile)` / `labPaymentDetails`, `planAmounts` / `splitInstallments` (whole rupees, remainder on the last), `buildSchedule` (installment N due N × tenure days after activation), `findLabPayment(wallet, instIndex)` (installment by index, or the down payment when the route has no `:instIndex` — lets one handler serve both receipt routes), `pktDay`.
- `config/travel.js` + `utils/travel.js` — True Cost: travel modes and PKR/km rates, round trip (×2), `routeDistances(origin, labs)` = one OSRM table request (road km + drive minutes), falling back to straight line × 1.3 (`source: 'approx'`) per lab; `haversineKm`, `isLatLng`.
- `utils/reportReader.js` → `utils/reportInterpreter.js` → `utils/reportSummary.js`, run by `utils/reportPipeline.js` in the background after a report upload (decision 9): Document Intelligence read (2-page PDF pieces via `pdf-lib`, photos over 4 MB shrunk to a JPEG copy with `sharp`), result rows compared with printed ranges, English + Urdu template summary, `autoRead` stored on the report, patient notified (`report_summary_ready`).
- `config/azure.js` + `utils/azure.js` — Azure Translator (`translateToUrdu`, returns null on failure) and Speech (`urduAudioFile(text, voice)` → cached MP3 in `storage/audio/`, gitignored and **not** served publicly; voices `uzma` = ur-PK-UzmaNeural default, `asad` = ur-PK-AsadNeural).
- `utils/schedule.js` — appointment scheduling in Pakistan time: dates are `"YYYY-MM-DD"`, times `"HH:MM"` (24h). `slotTimes(ranges, duration)` splits availability ranges ("09:00 AM – 01:00 PM"; a single time = one slot) into start times; `freeSlots` (future, not booked, next `BOOKING_WINDOW_DAYS` = 14 days incl. today); `pktDate`, `pktInstant(date, time)`, `isWithinBookingWindow`; `PATIENT_CANCEL_HOURS` = 2.
- `utils/legalAgreementTemplate.js` — `generateLegalAgreement` (default notice for the lawyer) and `generateInstallmentAgreement` (what the patient accepts; no date inside so the previewed text can be compared exactly at submit).
- `utils/generateToken.js` — JWT `{id, role}`.
- `utils/cnic.js` (`normalizeCnic` → `#####-#######-#`), `utils/fileUrl.js` (`fileUrl(subfolder, filename)`, `removeUploadedFiles(req)` for rejected uploads), `utils/patientProfiles.js` (`withPatientDetails(docs)` adds cnic/city/address/cnicStatus onto populated `patient`).
- `server.js` ends with a JSON error handler (multer + body-parse errors → `{ message }` 400).

### Models (`models/`)
- `User` — `role: admin|lawyer|lab|doctor|patient`, `status: pending|active|rejected|suspended`; bcrypt pre-save hook, `comparePassword`.
- `PatientProfile` — unique `cnic`, city, address, `cnicStatus: unverified|verified|rejected` (+ reason/reviewedAt/By). Patients are `active` on signup; admin verifies the CNIC; verified CNIC is required for community support (and installments, Step 2).
- `DoctorProfile` (specialization, experience, fee, `availability[{day, slots[{time}]}]` where `time` is a range like "09:00 AM – 01:00 PM" (`isBooked` is unused — bookings live in `Appointment`), `consultationDuration` (default 20, 5–120 min), bio, rating), `LabProfile` (labName, location, payment details, `coordinates {lat, lng}` map pin for True Cost, `isCharityPartner`, embedded `tests[]` with installment config: enabled/count/tenureDays ∈ {15,20,25,30}), `LawyerProfile`. Each 1:1 with User via `user`.
- `Wallet` — a patient's installment plan with a lab. `status: pending_approval → rejected | awaiting_fee → active → completed | defaulter` (default `pending_approval`). Stores plan terms copied from the test (`labTest`, `totalAmount`, `installmentCount`, `installmentTenureDays`), `guarantor`, `agreement {text, textUrdu, acceptedAt}`, review fields (`planApprovedAt/By`, `rejectionReason/At/By`, `activatedAt`). `downPayment` and each `installments[]` entry share the receipt chain (receipt → `labApproved` → `adminVerified`; installments also `status: pending|overdue|paid`). `serviceFee` is admin-verified only (+ `rejectionReason`). Pre-save: `remainingBalance = totalAmount − verified down payment − paid installments` (service fee excluded). `isFullyPaid()` = fee + down payment + all installments verified.
- `DefaulterCase`, `CommunityApplication` (pending → approved with `slip.slipId` + assigned lab → `testConducted`), `Prescription` (doctor → patient, list of tests, `appointment` — one per appointment), `TestReport` (lab → patient file URL, optional `booking`, `summary` + `summaryUrdu` (`summarySource: lab|auto`, `summaryUrduSource: machine|lab|auto`), `autoRead {status: pending|processing|ready|failed|skipped, kind: table|narrative|unreadable, findings[{name, result, unit, range, normalLow, normalHigh, status: high|low|abnormal|normal|unknown, basis}], pages, totalPages, error}`), `Notification` (typed enum, `meta` mixed).
- `Appointment` — patient + doctor + `date` / `time` (PKT) + `startsAt` (instant), `durationMinutes`, `fee` snapshot, `status: confirmed|cancelled|completed|no_show`, `cancelledBy` / `cancellationReason`. **Unique partial index on doctor + date + time where `status: 'confirmed'`** — the database rejects double-booking; cancelling frees the slot.
- `LabBooking` — patient + lab + `labTest` / `testName` / `price` snapshot + `visitDate` (no time), `paymentMethod: at_lab|installment` (+ `wallet`), `status: confirmed → sample_collected → completed | cancelled`, `report`.

### API (all JSON; mount prefix in parentheses)
- **auth** (`/api/auth`): `POST /register` (patient|lawyer|lab|doctor; patient needs `cnic` and starts `active`, providers start `pending`; creates role profile, rolls back User on failure; emails lowercased), `POST /login` (non-admin; must be `active`), `GET /me`.
- **patient** (`/api/patient`): profile get/put (CNIC editable until verified; change → `unverified`); `GET /prescriptions`; `GET /reports`, `PUT /reports/:id/read`; `GET /wallets` (each with `labName`, `labPayment`); installment plans: `GET /installment-plans/config` (fee, down-payment %, limit, CareFirst account, open plan count), `POST /installment-plans/preview` (`labId, testId, guarantor` → terms + `agreementText`), `POST /installment-plans` (same + `acceptAgreement: true` + the exact `agreementText`; 409 if the terms changed) → `pending_approval`; receipts (multipart `receipt`): `POST /wallets/:walletId/installments/:instIndex/receipt` and `/down-payment/receipt` (active plans; replaceable until lab confirms; notifies lab), `POST /wallets/:walletId/service-fee/receipt` (`awaiting_fee`; replaceable until verified; notifies admins); `GET|POST /community-applications` (multipart `testRequired` + `documents[]` ≤5; needs verified CNIC; one pending at a time; notifies admins); appointments: `GET /appointments` (with `doctorSpecialization` + `prescription`), `POST /appointments` (`doctorId, date, time` → auto-confirmed; 409 if the slot was just taken or the patient already has one at that time), `PUT /appointments/:id/cancel` (up to 2 h before); lab visits: `GET /lab-bookings`, `POST /lab-bookings` (`labId, testId, visitDate, walletId?` — wallet = an active/completed plan for that test at that lab, one booking per plan), `PUT /lab-bookings/:id/cancel` (before the visit date); notifications incl. `read-all`.
- **admin** (`/api/admin`): `POST /login` (username/password compared to env, returns token for seeded admin user); registrations list/approve/reject (providers only); users list (paginated, role/status filters; patients include `profile`)/suspend/activate; `PUT /patients/:userId/cnic/verify|reject`; wallets list/get (with patient CNIC + `labName`); plan review `PUT wallets/:walletId/approve` (→ `awaiting_fee`) / `reject` (`reason` required); `PUT wallets/:walletId/service-fee/verify` (→ `active`, schedule generated, patient + lab notified) / `service-fee/reject` (`reason`; clears the screenshot); `PUT wallets/:walletId/installments/:instIndex/verify` and `/down-payment/verify` (after lab confirmation); `GET defaulter-cases`; community-applications list/approve (`assignedLabId`)/reject; notifications.
- **lab** (`/api/lab`): profile get/put (`coordinates: {lat, lng}` or `null`); tests CRUD (`/tests/:testId`, embedded subdocs); `POST /reports/upload` (multipart field `report`, optional `summary` → translated to Urdu; body `patientId, testName, notes` — or `bookingId, notes`: patient + test from the booking, sample must be collected, links the report and completes the booking); bookings: `GET /bookings`, `PUT /bookings/:id/sample-collected`, `PUT /bookings/:id/complete`; `GET /reports`, `PUT /reports/:id/summary` (`summaryUrdu` = lab correction; `summary` alone = re-translate), `POST /reports/:id/read-again` (re-run the automatic reading); `GET /receipts` (active plans; `pendingDownPayment` + `pendingInstallments`) + `PUT /receipts/:walletId/installments/:instIndex/approve` and `/down-payment/approve`; needy-patients list + `PUT /:id/mark-conducted`; `GET /patients` (from bookings + wallets + community apps); notifications.
- **doctor** (`/api/doctor`): profile get/put; availability get/put (+ `consultationDuration`); `PUT /fee`; appointments: `GET /appointments` (with patient CNIC + prescription), `PUT /appointments/:id/cancel` (`reason` required, sent to the patient), `/complete`, `/no-show` (after the start time); `GET /patients` (from appointments); prescriptions: `POST /prescriptions` (`appointmentId, tests[], generalNotes` — appointment started, not cancelled / no-show, one per appointment), `GET /prescriptions`; `GET /reports` (reports of patients this doctor prescribed for); notifications.
- **lawyer** (`/api/lawyer`): `GET /defaulter-cases[/:id]` (own cases only); notifications incl. `PUT /notifications/read-all` (declared before `/:id/read`).
- **public** (`/api/public`): `GET /tests` — active tests of active labs, grouped by lab, with `acceptsInstallments` (lab has payment details) and `hasLocation`; `GET /true-cost?lat&lng&mode` — per lab `distanceKm`, `durationMin`, round-trip `travelCost`, `source: road|approx|no_location` (position not stored); `GET /doctors` — active doctors with fee, rating, available days, consultation duration; `GET /doctors/:doctorId/slots` — free future start times per day for the next 14 days. No auth.
- **tts** (`/api/tts`, any signed-in active user): `GET /status`; `POST /` `{ source: 'agreement'|'report', id, voice? }` or `{ source: 'agreement-preview', labId, testId, guarantor, voice? }` (patient, before applying) → `audio/mpeg`. Speaks only Urdu text the server stores/generates; access: agreement → owning patient, admin, assigned lawyer; report → patient, uploading lab, a doctor who prescribed for the patient, admin; otherwise 404.
- `GET /api/health`.

Controller convention: one async function per endpoint, `try { ... } catch (err) { res.status(500).json({ message: err.message }) }`, errors as `{ message }`. Installments are addressed by array **index**, not id.

## Known gaps (as of 2026-10-02)
- No rejection step for lab/admin on down-payment or installment receipts (only the service fee can be rejected); the patient can replace a receipt only until the lab confirms it.
- The down payment is not escalated by the defaulter job — only installments are.
- Uploaded files (reports, receipts, community docs) are served publicly from `/uploads` with unguessable names but no auth.
- No appointment or lab-visit reminders (only installment due reminders exist); no limit on how many future appointments one patient can hold.
- Lab visits have no opening-days check — any date in the next 14 days can be booked.
- True Cost uses the public OSRM demo server (fair-use, no SLA) — fine for the FYP; a production deployment would need its own OSRM or a paid routing API. Patient coordinates are sent to OSRM and report summaries / agreement text to Azure (mention in the report's privacy section).
- The Urdu agreement template should be proofread by a native speaker on the team; agreements created before Step 4 have no Urdu version.
- `adminController.js` imports `{ v4 }` from `crypto` (doesn't exist; unused).
- `db.js` logs the default admin password.

# Project status & roadmap (handoff, 2026-10-02)

## Context
Final Year Project, FAST-NUCES Chiniot, 2026. Team: **M. Makki** (repo owner, `makki-Q`), **Ali Anjum**, **Umar Maqbool**. Supervisor Muhammad Haseeb Arshad, co-supervisor Hamza Yousaf.
Requirements live in the repo root: `SRS-carefirst.pdf` (21 use cases, UC-01…UC-21) and `FYP Proposal makki.docx` (features 1.4.1–1.4.10). Proposal title: *"CareFirst: A web-based Smart Healthcare Appointment & Diagnostic Installment Management Platform"*.

Principles from the proposal that every feature must respect:
- The platform **never handles or transfers money**. Patients pay labs directly; CareFirst only records payment proofs. It is a facilitator and record keeper — not a bank, medical authority or charity.
- A **separate fixed platform service fee** is charged for installment tracking.
- **CNIC** identifies users; installment use requires accepting a **digital legal agreement**.
- No online consultation — appointments are **physical clinic visits**.

## How to work with Makki
- Ask before making product decisions that aren't settled below; he answers quickly.
- Keep new code in the existing directories and follow the existing patterns (see Controller convention above).
- Verify end to end before calling something done (build the frontend + run an API test against a throwaway DB — see "Testing").

## Decisions already made
1. **Patients are `active` immediately on signup.** They give a **CNIC number only** (no CNIC photos at signup). An admin verifies the CNIC later (Admin → Manage Users → Verify/Reject CNIC).
2. A **verified CNIC is required** for community support applications, and must also gate installment plans (Step 2). A rejected CNIC can be corrected from the patient's Profile page, which sends it back to `unverified`. A verified CNIC is locked.
3. **Receipts are uploaded by the patient** (proposal 1.4.8). Chain: patient uploads → lab confirms it received the cash → admin verifies → installment `paid`. A receipt can be replaced until the lab confirms.
4. **Donations are not collected by the platform** (proposal 1.4.10); admin only shows partner labs' donation channels.
5. **Defaulter escalation is automatic** (nightly cron, 3-day grace period, assigned to the least-loaded lawyer). The job only looks at `active` plans.
6. **Installment plans (Step 2, decided 2026-10-02).** CareFirst is not a middleman for test payments: down payment and installments go **directly to the lab**. The only money paid to CareFirst is the **service fee**, and only when a patient opts into an installment plan.
   - **Apply:** patient with a verified CNIC picks an installment-enabled test, enters guarantor details, reads and accepts the legal agreement (text + acceptance time stored) → wallet `pending_approval`. Pending applications count toward the **max 2 open plans** per patient (open = `pending_approval`, `awaiting_fee` — approved, fee not yet verified — `active` or `defaulter`).
   - **Guarantor:** name, phone and relation required; CNIC required, valid and different from the patient's; address optional.
   - **Admin approves or rejects** (rejection needs a reason; patient notified). No lab acceptance step.
   - **Service fee:** PKR 500 (`SERVICE_FEE_PKR`), paid to CareFirst's account (`CAREFIRST_*` in `.env`). Patient uploads a screenshot; **admin verifies it directly** (no lab step).
   - **Activation:** once the fee is verified the wallet becomes `active` and the schedule is generated: down payment = 20% of the test price (`DOWN_PAYMENT_PERCENT`, whole rupees), the rest split into `installmentCount` installments, whole rupees with the remainder on the last one. **Tenure is the gap between installments**; the first installment is due one tenure after activation. The lab is notified.
   - **Down payment and installments** use the same receipt chain: patient uploads a screenshot → lab confirms → admin verifies. The patient sees the lab's own payment details from `LabProfile` (bankDetails, jazzCash, easyPaisa). A lab with no payment details cannot receive applications and is prompted to add them.
   - **Balance:** `remainingBalance = totalAmount − verified down payment − paid installments` (the service fee is separate). `completed` = fee verified + down payment verified + all installments paid.
   - **Reminders:** notifications 3 days and 1 day before each due date.
7. **Appointments and lab bookings (Step 3, decided 2026-10-02).** No money flows through CareFirst: the consultation fee is paid at the clinic and lab tests at the lab (or through the patient's installment plan); the app only shows prices.
   - **Doctor appointments** are auto-confirmed when the patient picks a free slot (no doctor approval); doctor and patient are notified. Statuses `confirmed | cancelled | completed | no_show`.
   - **Slots:** patients book a specific date within the next 14 days (today included), using the doctor's weekly availability as the template. Availability is stored as time ranges ("09:00 AM – 01:00 PM"); each range is split into bookable times by the doctor's **consultation duration** (`DoctorProfile.consultationDuration`, default 20 min, editable on Manage Availability). Only free future times are offered. Double-booking is prevented in the database: unique index on doctor + date + time for `confirmed` appointments.
   - **Cancellation:** the patient can cancel up to 2 hours before the start; the doctor can cancel any time while it is confirmed but must give a reason, which is sent to the patient. After the start time the doctor marks it `completed` or `no_show`.
   - **Prescriptions attach to an appointment** (one per appointment, written once the appointment has started and it isn't cancelled / no-show). The doctor's patient list comes from their appointments — no raw patientId input. On the patient side each prescribed test has a "Find labs" button that opens Book Tests filtered to that test.
   - **Lab bookings:** test + visit date (no time; within the next 14 days), auto-confirmed, paid at the lab or through one of the patient's active/completed installment plans for that test at that lab (a plan covers one booking). Statuses `confirmed → sample_collected → completed`, or `cancelled`. The patient can cancel before the visit date. The lab marks sample collected / completed; uploading a report for a booking links it and completes the booking (sample must be collected first).
8. **True Cost Analysis and Urdu text-to-speech (Step 4, decided 2026-10-03).**
   - **Lab location:** the lab drops a pin on an OpenStreetMap (Leaflet) map, or uses its current location, on Test Catalog; stored as coordinates on `LabProfile`. A warning shows until it's set.
   - **Patient location:** browser geolocation (or a dropped pin) when True Cost is switched on; used for the calculation only, never stored.
   - **Distance:** road distance + drive time from the public OSRM service (one table request for all labs, URL in `.env`); if OSRM fails, straight-line distance × 1.3, labelled approximate.
   - **Travel cost:** the patient picks how they travel — motorbike PKR 8/km, car PKR 25/km, rickshaw/ride-hailing PKR 50/km (defaults, editable in `.env`); cost = km × 2 (round trip, one visit) × rate. True cost = test price + travel cost; labs sorted by true cost for a searched test, "Best value" badge; labs without a location listed last.
   - **Urdu text:** the installment agreement has a fixed Urdu template (team proofreads) filled with the same details and stored next to the English one (English stays binding). Report summaries: the lab writes a short English summary when uploading; **Azure Translator** translates it to Urdu; the lab can review and correct the Urdu. Urdu is shown right-to-left in a Nastaliq font.
   - **Urdu audio:** **Azure Speech**, voice ur-PK Uzma (female) by default with a toggle to Asad (male). The browser asks for a specific agreement / report; the server checks access, generates or reuses cached audio (private folder, not `/uploads`) and streams it — keys never reach the browser and no arbitrary text is accepted. Listen buttons: agreement (patient Apply page, My Wallet, lawyer case view) and report summaries (patient My Reports / Appointments, doctor Patient Reports).
   - Keys in `.env` (`AZURE_SPEECH_KEY/REGION`, `AZURE_TRANSLATOR_KEY/REGION`); without them translation is skipped and Listen explains audio isn't configured. The e2e test uses a local fake Azure server.

9. **Automatic lab report summary (decided 2026-10-04).** Reports are hard for patients to read and labs may not write a summary, so every uploaded report is read automatically and the summary goes **straight to the patient** (no review step), always telling them to share the report with their doctor and visit them.
   - **Reading:** Azure AI Document Intelligence (`prebuilt-layout`, free tier F0 — reads 2 pages per request and ~4 MB per file, so PDFs are sent in 2-page pieces, up to 12 pages per report; a photo over 4 MB is sent as a smaller JPEG copy (≤3000 px, made with `sharp`) — the stored original is untouched). Works on scans; OCR noise is cleaned up.
   - **Understanding without AI:** our own rules (`utils/reportInterpreter.js`) find result tables and compare each value only with the normal range **printed on the report** (or the lab's own High/Low flag): graded bands, sex-specific ranges (sex read from the report), word results (Nil / Negative / ++), count pairs. A stand-alone "Positive / Reactive / Detected" line outside a table is always flagged. Anything that can't be compared is shown as "ask your doctor", never as normal.
   - **Summary:** fixed English + Urdu templates (no machine translation) listing what is outside the range; an all-normal result never claims the whole report is normal. **Written reports (histopathology, radiology) are not summarised** — the patient is told a doctor needs to explain it (we never read a diagnosis like "metastatic adenocarcinoma" aloud automatically).
   - The patient sees the flagged results, the summary with Urdu Listen, a "see your doctor" box with **Book a doctor**, and "created automatically — check the original report". A lab-written summary always wins; the lab can still edit, and can **Read again** a failed report.
   - Sample reports for development live in `lab-reports/` (gitignored — real patient data).
