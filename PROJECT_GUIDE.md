# CareFirst — Codebase Index

Healthcare platform (Pakistan, PKR) connecting patients, doctors, labs, lawyers and an admin. Core idea: lab tests paid in **installments**, with a 3-step receipt verification flow and automatic **legal escalation** of defaulters. Also a **community support** (charity) track for needy patients.

Two independent apps in one git repo (GitHub: `makki-Q/carefirst`, branch `main`), no automated test suite in the repo, no monorepo tooling:

| Dir | Stack | Run |
|---|---|---|
| `carefirst-backend/` | Node (CommonJS), Express 4, Mongoose 7, Socket.IO 4, multer, node-cron, JWT | `npm run dev` (nodemon) → :5000 |
| `carefirst-web-modified/` | React 19, Vite 8, Tailwind 4 (auth pages only), mix of `.jsx` and `.tsx` | `npm run dev` → :5173, proxies `/api` and `/socket.io` to :5000 |

Env (`carefirst-backend/.env.example`): `PORT, MONGO_URI, JWT_SECRET, JWT_EXPIRES_IN, ADMIN_USERNAME, ADMIN_PASSWORD, CLIENT_URL, BASE_URL`; report reading (`AZURE_DOCINTEL_ENDPOINT/KEY`); installment settings (`SERVICE_FEE_PKR`, `DOWN_PAYMENT_PERCENT`, `CAREFIRST_*`); True Cost (`TRAVEL_RATE_MOTORBIKE/CAR/RIDE`, `OSRM_URL`); Azure (`AZURE_TRANSLATOR_KEY/REGION`, `AZURE_SPEECH_KEY/REGION`, optional `AZURE_*_ENDPOINT`, `AUDIO_CACHE_DIR`). The real Azure keys live only in the local `.env` (gitignored) — never commit them.
Project lives at `C:\dev\carefirst` (Windows). Do **not** work in the old OneDrive copy (`OneDrive\Desktop\carefirst2`) — it is obsolete, and OneDrive placeholders made Node fail with `UNKNOWN: unknown error, read`.
`C:\Program Files\nodejs` was added to the user PATH on 2026-10-04 (new terminals find `node`/`npm`; restart VS Code to pick it up). In an older shell use `"/c/Program Files/nodejs/node.exe"` or `export PATH="/c/Program Files/nodejs:$PATH"`. Stopping a background `npm run dev` can leave nodemon/vite running — check ports 5000/5173 and kill the node processes. MongoDB runs locally on `localhost:27017` (dev database `carefirst`).

## Backend (`carefirst-backend/`)

- `server.js` — wires middleware, routes, Socket.IO, 404 handler; on DB connect starts the cron job. Serves `uploads/` statically.
- `config/installments.js` — Step 2 settings from `.env`: `SERVICE_FEE` (`SERVICE_FEE_PKR`, default 250), `DOWN_PAYMENT_PERCENT` (default 20), `CAREFIRST_ACCOUNT` (`CAREFIRST_BANK_NAME/ACCOUNT_TITLE/ACCOUNT_NUMBER/JAZZCASH/EASYPAISA`), plus constants `MAX_OPEN_PLANS` 2, `GRACE_DAYS` 3, `REMINDER_DAYS` [3, 1].
- `utils/platformSettings.js` — `getPlatformSettings()` → `{ careFirstAccount, supportEmail, saved, updatedAt }`: what the admin saved on Settings (`PlatformSettings` model, single doc `key: 'platform'`), otherwise the `.env` `CAREFIRST_*` values. Use this (not `CAREFIRST_ACCOUNT`) wherever the CareFirst account is shown.
- `controllers/adminInsightsController.js` — admin overview, monthly reports and settings (real data; months are Pakistan calendar months).
- `config/db.js` — Mongo connect + seeds one `admin` user if none exists.
- `middleware/auth.js` — `protect` (Bearer JWT → `req.user`), `requireRole(...roles)`, `requireActive` (status must be `active`). Routers use a `guard = [protect, requireRole(x), requireActive]` array.
- `middleware/upload.js` — multer disk storage into `uploads/{reports,receipts,community-docs}`; pdf/jpg/png, 10 MB. `uploadCnicPictures` (fields `patientCnicFront/Back`, `guarantorCnicFront/Back`, jpg/png) writes to the **private** `CNIC_DIR` (`storage/cnic/`, env `CNIC_STORAGE_DIR`; gitignored, not served statically).
- `socket/notificationSocket.js` — clients emit `join(userId)` to enter a room; server emits `notification:new`. `sendNotification(userId, doc)` is called from controllers/job. Room join is not authenticated.
- `jobs/defaulterJob.js` — daily 00:05 Asia/Karachi. Pending installments past due + 3 grace days with no receipt → `overdue`; first time escalates wallet to `defaulter`, creates `DefaulterCase` with generated legal text (`utils/legalAgreementTemplate.js`), assigns the active lawyer with fewest active cases, notifies lawyer/admins/patient. Escalated (`defaulter`) plans keep being checked: a later installment falling overdue updates the open case (only an `active` case counts — a closed one never re-opens). Then `runDueReminders()`: `installment_due_soon` notifications 3 and 1 Pakistan calendar days before each due date (skipped once a receipt is uploaded; sent days stored in `installments[].remindersSent`), `active` wallets only.
- `utils/defaulters.js` (decision 14) — `restrictionFor(patientId)` (null, or `{plans, overdueCount, overdueTotal}`), `notRestricted` route guard (403 `{restricted: true}`), `clearDefaultIfPaid(wallet, {resolution, note, by})` (no overdue installment left → plan `active`/`completed`, case `resolved`, patient / lawyer / admins notified; otherwise refreshes the open case's figures).
- `utils/installmentPlan.js` — `OPEN_PLAN_STATUSES`, `hasPaymentDetails(labProfile)` / `labPaymentDetails`, `planAmounts` / `splitInstallments` (whole rupees, remainder on the last), `buildSchedule` (installment N due N × tenure days after activation), `findLabPayment(wallet, instIndex)` (installment by index, or the down payment when the route has no `:instIndex` — lets one handler serve both receipt routes), `pktDay`.
- `config/travel.js` + `utils/travel.js` — True Cost: travel modes and PKR/km rates, round trip (×2), `routeDistances(origin, labs)` = one OSRM table request (road km + drive minutes), falling back to straight line × 1.3 (`source: 'approx'`) per lab; `haversineKm`, `isLatLng`.
- `utils/reportReader.js` → `utils/reportInterpreter.js` → `utils/reportSummary.js`, run by `utils/reportPipeline.js` in the background after a report upload (decision 9): Document Intelligence read (2-page PDF pieces via `pdf-lib`, photos over 4 MB shrunk to a JPEG copy with `sharp`), result rows compared with printed ranges, English + Urdu template summary, `autoRead` stored on the report, patient notified (`report_summary_ready`).
- `config/azure.js` + `utils/azure.js` — Azure Translator (`translateToUrdu`, returns null on failure) and Speech (`urduAudioFile(text, voice)` → cached MP3 in `storage/audio/`, gitignored and **not** served publicly; voices `uzma` = ur-PK-UzmaNeural default, `asad` = ur-PK-AsadNeural).
- `utils/schedule.js` — appointment scheduling in Pakistan time: dates are `"YYYY-MM-DD"`, times `"HH:MM"` (24h). `slotTimes(ranges, duration)` splits availability ranges ("09:00 AM – 01:00 PM"; a single time = one slot) into start times; `freeSlots` (future, not booked, next `BOOKING_WINDOW_DAYS` = 14 days incl. today); `pktDate`, `pktInstant(date, time)`, `isWithinBookingWindow`; `PATIENT_CANCEL_HOURS` = 2.
- `utils/legalAgreementTemplate.js` — `generateLegalAgreement` (default notice for the lawyer) and `generateInstallmentAgreement` (what the patient accepts; no date inside so the previewed text can be compared exactly at submit).
- `utils/slips.js` — slip numbers (`AP-`/`LB-`/`CS-` + `XXXX-XXXX`, no 0/O/1/I), `withSlipNumber` mongoose plugin (sets `slipNumber` on new Appointment / LabBooking docs), `backfillSlipNumbers()` (run at startup for older bookings). `utils/slipPdf.js` — `buildSlipPdf(slip, { attachments })` one-page A4 slip with pdf-lib (standard fonts: non-Latin text becomes `?`); attachments = `/uploads` URLs added after it (pictures shrunk with sharp, PDFs ≤ 10 pages each).
- `utils/labBranches.js` — `offersTest(test, branchId)`, `branchesOffering`, `branchView` (public shape with `branchId`, `hasLocation`), `cleanBranchInput`, `ensureBranch`, `backfillLabBranches()` (run at startup before `backfillSlipNumbers`: a lab without branches gets one from its name / location / pin, old bookings get that branch).
- `scripts/import-dataset.js` (`npm run import:dataset`) — imports `dataset/clean/*.csv` (5 Faisalabad lab chains with branches + tests, 28 doctors) into `MONGO_URI` as active accounts, password `password123`; upserts by e-mail / branch name / test name, deletes nothing. Details in `dataset/README.md`.
- `utils/generateToken.js` — JWT `{id, role}`.
- `utils/cnic.js` (`normalizeCnic` → `#####-#######-#`), `utils/fileUrl.js` (`fileUrl(subfolder, filename)`, `removeUploadedFiles(req)` for rejected uploads), `utils/patientProfiles.js` (`withPatientDetails(docs)` adds cnic/city/address/cnicStatus onto populated `patient`).
- `server.js` ends with a JSON error handler (multer + body-parse errors → `{ message }` 400).

### Models (`models/`)
- `User` — `role: admin|lawyer|lab|doctor|patient`, `status: pending|active|rejected|suspended`; bcrypt pre-save hook, `comparePassword`.
- `PatientProfile` — unique `cnic`, city, address, `cnicStatus: unverified|verified|rejected` (+ reason/reviewedAt/By). Patients are `active` on signup; admin verifies the CNIC; verified CNIC is required for community support; installment applications only need a CNIC that isn't `rejected` (approving the plan verifies it, decision 10).
- `DoctorProfile` (specialization, experience, fee, `availability[{day, slots[{time}]}]` where `time` is a range like "09:00 AM – 01:00 PM" (`isBooked` is unused — bookings live in `Appointment`), `consultationDuration` (default 20, 5–120 min), bio, rating, `clinicName` / `clinicAddress` (optional; on the appointment slip and in Find Doctors)), `LabProfile` (labName, location, payment details, `branches[{name, address, area, phone, hours, coordinates {lat, lng}}]` (at least one; decision 12), legacy `coordinates` (kept, not used for True Cost), `isCharityPartner` + `charityPartnerSince` (Community Support partner, decision 4), embedded `tests[]` with installment config: enabled/count/tenureDays ∈ {15,20,25,30} and `branches[]` (branch ids; empty = every branch)), `LawyerProfile`. Each 1:1 with User via `user`.
- `Wallet` — a patient's installment plan with a lab. `status: pending_approval → rejected | awaiting_fee → active → completed | defaulter` (default `pending_approval`). Stores plan terms copied from the test (`labTest`, `totalAmount`, `installmentCount`, `installmentTenureDays`), `patientCnic` + `patientAddress` (as in the agreement), `guarantor`, `cnicPictures {patientFront, patientBack, guarantorFront, guarantorBack}` (file names in `CNIC_DIR`), `agreement {text, textUrdu, acceptedAt}`, review fields (`planApprovedAt/By`, `rejectionReason/At/By`, `activatedAt`). `downPayment` and each `installments[]` entry share the receipt chain (receipt → `labApproved` → `adminVerified`; installments also `status: pending|overdue|paid`). `serviceFee` is admin-verified only (+ `rejectionReason`). Down payment and installments also carry `rejectionReason/At/By (lab|admin)` when a receipt was turned down, and installments `settledOffline {at, by, note}` when the lawyer closed a case. Pre-save: `remainingBalance = totalAmount − verified down payment − paid installments` (service fee excluded). `isFullyPaid()` = fee + down payment + all installments verified.
- `DefaulterCase` (`status: active|resolved`, `resolution: paid|settled`, `resolutionNote`, `resolvedAt/By`), `CommunityApplication` (pending → approved with `slip.slipId` (`CS-XXXX-XXXX`; older data has `SLP-######`) + assigned lab → `testConducted`), `Prescription` (doctor → patient, list of tests, `appointment` — one per appointment), `TestReport` (lab → patient file URL, optional `booking`, `summary` + `summaryUrdu` (`summarySource: lab|auto`, `summaryUrduSource: machine|lab|auto`), `autoRead {status: pending|processing|ready|failed|skipped, kind: table|narrative|unreadable, findings[{name, result, unit, range, normalLow, normalHigh, status: high|low|abnormal|normal|unknown, basis}], pages, totalPages, error}`, `sharedWith[{doctor, sharedAt}]` — the only doctors who may see it, decision 13), `Notification` (typed enum, `meta` mixed).
- `Appointment` — patient + doctor + `date` / `time` (PKT) + `startsAt` (instant), `durationMinutes`, `fee` snapshot, `status: confirmed|cancelled|completed|no_show`, `cancelledBy` / `cancellationReason`. **Unique partial index on doctor + date + time where `status: 'confirmed'`** — the database rejects double-booking; cancelling frees the slot. `slipNumber` (`AP-…`, unique).
- `LabBooking` — patient + lab + `labTest` / `testName` / `price` snapshot + `visitDate` (no time), `paymentMethod: at_lab|installment` (+ `wallet`), `status: confirmed → sample_collected → completed | cancelled`, `report`. `slipNumber` (`LB-…`, unique). `branch` + `branchName` / `branchAddress` snapshot, `transfers[{fromName, toName, by: patient|lab, at}]`.

`GET /reports` (with `sharedWith[].doctor.name`), `PUT /reports/:id/read`; report sharing (decision 13): `GET /report-doctors` (doctors with a `confirmed` or `completed` appointment → `{doctorId, name, specialization}`), `PUT /reports/:id/share` (`doctorId`; 400 for any other doctor; sharing twice keeps one entry; notifies the doctor `report_shared`), `DELETE /reports/:id/share/:doctorId` (stop sharing); `GET /wallets` (each with `labName`, `labPayment`); installment plans: `GET /installment-plans/config` (fee, down-payment %, limit, CareFirst account, open plan count), `POST /installment-plans/preview` (`labId, testId, patientAddress, guarantor` → terms + `agreementText`), `POST /installment-plans` (**multipart**: field `data` = JSON of the same + `acceptAgreement: true` + the exact `agreementText`, plus the four CNIC pictures; 409 if the terms changed; 400 + files removed if anything is missing) → `pending_approval`; receipts (multipart `receipt`): `POST /wallets/:walletId/installments/:instIndex/receipt` and `/down-payment/receipt` (active and `defaulter` plans; replaceable until lab confirms; a new upload clears a rejection; notifies lab), `POST /wallets/:walletId/service-fee/receipt` (`awaiting_fee`; replaceable until verified; notifies admins); `GET|POST /community-applications` (multipart `testRequired` + `documents[]` ≤5; 409 if the slot was just taken or the patient already has one at that time), `PUT /appointments/:id/cancel` (up to 2 h before); lab visits: `GET /lab-bookings`, `POST /lab-bookings` (`labId, testId, visitDate, branchId?, walletId?` — branch required when several branches offer the test (400), chosen automatically when only one does; wallet = an active/completed plan for that test at that lab, one booking per plan), `PUT /lab-bookings/:id/branch` (`branchId`; while `confirmed`; the branch must offer the test; notifies the lab), `PUT /lab-bookings/:id/cancel` (before the visit date); notifications incl. `read-all`.
- **admin** (`/api/admin`): `POST /login` (username/password compared to env, returns token for seeded admin user); registrations list/approve/reject (providers only); users list (paginated, role/status filters; patients include `profile`)/suspend/activate; `PUT /patients/:userId/cnic/verify|reject`; wallets list/get (with patient CNIC + `labName`); plan review `PUT wallets/:walletId/approve` (→ `awaiting_fee`; also verifies the patient's CNIC + `cnic_verified` notification; 409 if the profile CNIC no longer matches `wallet.patientCnic`) / `reject` (`reason` required); `PUT wallets/:walletId/service-fee/verify` (→ `active`, schedule generated, patient + lab notified) / `service-fee/reject` (`reason`; clears the screenshot); `PUT wallets/:walletId/installments/:instIndex/verify` and `/down-payment/verify` (after lab confirmation; verifying the last overdue installment of a `defaulter` plan clears it), `.../reject` (`reason`; clears the receipt and the lab's confirmation; patient + lab notified); users list adds `isDefaulter` on patients; `GET defaulter-cases` includes patient CNIC, open and closed cases and `wallet.labName`; `GET defaulter-cases`; community-applications list/approve (`assignedLabId` — must be a partner lab)/reject; `GET /partner-labs` (labs in Community Support with `assigned` / `conducted` counts); notifications. `GET /overview` (totals by role, today's appointments / lab visits, open plans, latest activity); `GET /reports?month=YYYY-MM` (monthly counts + previous month; bad / future month → current); `GET|PUT /settings` (`careFirstAccount {bankName, accountTitle, accountNumber, jazzCash, easyPaisa}` — at least one way to pay, bank needs name + title, wallet numbers `03XX-XXXXXXX` — and `supportEmail`).
- **lab** (`/api/lab`): profile get/put (`coordinates: {lat, lng}` or `null` — only for a lab with one branch, sets that branch's pin; otherwise 400); branches: `GET|POST /branches`, `PUT|DELETE /branches/:branchId` (unique names → 409; not the last branch → 400; not with open visits → 409; removing one switches off tests offered only there; renaming updates open bookings); tests CRUD (`/tests/:testId`, embedded subdocs; `branches: [branchId]`, all branches stored as `[]`); `PUT /bookings/:id/transfer` (`branchId`; "take this visit at my branch" while `confirmed`; the branch must offer the test; notifies the patient); `POST /reports/upload` (multipart field `report`, optional `summary` → translated to Urdu; body `patientId, testName, notes` — or `bookingId, notes`: patient + test from the booking, sample must be collected, links the report and completes the booking); bookings: `GET /bookings`, `PUT /bookings/:id/sample-collected`, `PUT /bookings/:id/complete`; `GET /reports`, `PUT /reports/:id/summary` (`summaryUrdu` = lab correction; `summary` alone = re-translate), `POST /reports/:id/read-again` (re-run the automatic reading); `GET /receipts` (active and `defaulter` plans, `defaulter: true` on escalated ones; `pendingDownPayment` + `pendingInstallments`) + `PUT /receipts/:walletId/installments/:instIndex/approve` and `/down-payment/approve`, `.../reject` (`reason`, before confirming; patient notified); needy-patients list + `PUT /:id/mark-conducted`; `GET /earnings` (this + last month: completed visits paid at the lab + down payments / installments the lab confirmed; `total`, `count`, `previousTotal`, `entries`); `PUT /community-support` (`{ join: true|false }`; leave → 409 while assigned tests wait; the general profile update no longer changes `isCharityPartner`); `GET /patients` (from bookings + wallets + community apps); notifications.
- **doctor** (`/api/doctor`): profile get/put (+ `clinicName`, `clinicAddress`); availability get/put (+ `consultationDuration`); `PUT /fee`; appointments: `GET /appointments` (with patient CNIC + prescription), `PUT /appointments/:id/cancel` (`reason` required, sent to the patient), `/complete`, `/no-show` (after the start time); `GET /patients` (from appointments); prescriptions: `POST /prescriptions` (`appointmentId, tests[], generalNotes` — appointment started, not cancelled / no-show, one per appointment), `GET /prescriptions`; `GET /reports` (only reports patients shared with this doctor, with `sharedAt`; who else it is shared with is not returned); notifications.
- **lawyer** (`/api/lawyer`): `GET /defaulter-cases[/:id]` (own cases only, open and closed), `PUT /defaulter-cases/:id/close` (`note` ≥ 5 chars; overdue installments recorded as settled, plan + account back to normal); notifications incl. `PUT /notifications/read-all` (declared before `/:id/read`).
- **public** (`/api/public`): `GET /tests` — active tests of active labs, grouped by lab, with `acceptsInstallments` (lab has payment details), `hasLocation`, `branches` and `tests[].branchIds` (null = every branch); `GET /true-cost?lat&lng&mode` — per lab the nearest branch's `distanceKm`, `durationMin`, round-trip `travelCost`, `source: road|approx|no_location` + `branchId`, and `branches[]` with the same figures per branch (position not stored); `GET /doctors` — active doctors with fee, rating, available days, consultation duration; `GET /doctors/:doctorId/slots` — free future start times per day for the next 14 days. No auth.
- **documents** (`/api/documents`, any signed-in active user): `GET /wallets/:walletId/cnic/:picture` (`patient-front|patient-back|guarantor-front|guarantor-back`) → the image, `Cache-Control: private, no-store`; only the owning patient, an admin or the lawyer assigned to that wallet's defaulter case, otherwise 404. **Slips** (PDF download, `Content-Disposition: attachment`): `GET /slips/appointment/:id` (patient, that doctor, admin), `GET /slips/lab-booking/:id` (patient, that lab, admin), `GET /slips/community/:id` (patient, the assigned lab, admin; approved only; the uploaded documents follow the slip page); cancelled bookings → 409, anyone else → 404.
- **tts** (`/api/tts`, any signed-in active user): `GET /status`; `POST /` `{ source: 'agreement'|'report', id, voice? }` or `{ source: 'agreement-preview', labId, testId, patientAddress, guarantor, voice? }` (patient, before applying) → `audio/mpeg`. Speaks only Urdu text the server stores/generates; access: agreement → owning patient, admin, assigned lawyer; report → patient, uploading lab, a doctor it is shared with, admin; otherwise 404.
- `GET /api/health`.

Controller convention: one async function per endpoint, `try { ... } catch (err) { res.status(500).json({ message: err.message }) }`, errors as `{ message }`. Installments are addressed by array **index**, not id.

Principles from the proposal that every feature must respect:
- The platform **never handles or transfers money**. Patients pay labs directly; CareFirst only records payment proofs. It is a facilitator and record keeper — not a bank, medical authority or charity.
- A **separate fixed platform service fee** is charged for installment tracking.
- **CNIC** identifies users; installment use requires accepting a **digital legal agreement**.
- No online consultation — appointments are **physical clinic visits**.

## Decisions already made
1. **Patients are `active` immediately on signup.** They give a **CNIC number only** (no CNIC photos at signup). An admin verifies the CNIC later (Admin → Manage Users → Verify/Reject CNIC).
2. A **verified CNIC is required** for community support applications. For installment plans see decision 10 (CNIC pictures with the application; approval verifies the CNIC). A rejected CNIC can be corrected from the patient's Profile page, which sends it back to `unverified`. A verified CNIC is locked.
3. **Receipts are uploaded by the patient** (proposal 1.4.8). Chain: patient uploads → lab confirms it received the cash → admin verifies → installment `paid`. A receipt can be replaced until the lab confirms.
4. **No donations through CareFirst** (proposal 1.4.10). Community Support **partner labs** take care of needy patients; CareFirst shows no donation channels and collects nothing (decided 2026-10-04).
   - A lab **joins Community Support from its own portal** (Needy Patients → Join), effective at once; admins are notified. It can **leave** only when every assigned needy patient's test is marked conducted.
   - The admin's Community Support page lists the partner labs (waiting / conducted counts); when approving an application **only partner labs can be assigned** (enforced by the API).
5. **Defaulter escalation is automatic** (nightly cron, 3-day grace period, assigned to the least-loaded lawyer). The job only looks at `active` plans.
6. **Installment plans (Step 2, decided 2026-10-02).** CareFirst is not a middleman for test payments: down payment and installments go **directly to the lab**. The only money paid to CareFirst is the **service fee**, and only when a patient opts into an installment plan.
   - **Apply:** patient whose CNIC is not `rejected` (see decision 10) picks an installment-enabled test, enters guarantor details, reads and accepts the legal agreement (text + acceptance time stored) → wallet `pending_approval`. Pending applications count toward the **max 2 open plans** per patient (open = `pending_approval`, `awaiting_fee` — approved, fee not yet verified — `active` or `defaulter`).
   - **Guarantor:** name, phone, relation and address required; CNIC required, valid and different from the patient's. The patient's own address is required too (decision 10).
   - **Admin approves or rejects** (rejection needs a reason; patient notified). No lab acceptance step.
   - **Service fee:** PKR 250 (`SERVICE_FEE_PKR`; changed from 500 on 2026-10-04), paid to CareFirst's account, which the **admin sets on Settings** (falls back to `CAREFIRST_*` in `.env` until saved). Patient uploads a screenshot; **admin verifies it directly** (no lab step).
   - **Activation:** once the fee is verified the wallet becomes `active` and the schedule is generated: down payment = 20% of the test price (`DOWN_PAYMENT_PERCENT`, whole rupees), the rest split into `installmentCount` installments, whole rupees with the remainder on the last one. **Tenure is the gap between installments**; the first installment is due one tenure after activation. The lab is notified.
   - **Down payment and installments** use the same receipt chain: patient uploads a screenshot → lab confirms → admin verifies. The patient sees the lab's own payment details from `LabProfile` (bankDetails, jazzCash, easyPaisa). A lab with no payment details cannot receive applications and is prompted to add them.
   - **Balance:** `remainingBalance = totalAmount − verified down payment − paid installments` (the service fee is separate). `completed` = fee verified + down payment verified + all installments paid.
   - **Reminders:** notifications 3 days and 1 day before each due date.
7. **Appointments and lab bookings (Step 3, decided 2026-10-02).** No money flows through CareFirst: the consultation fee is paid at the clinic and lab tests at the lab (or through the patient's installment plan); the app only shows prices.
   - **Doctor appointments** are auto-confirmed when the patient picks a free slot (no doctor approval); doctor and patient are notified. Statuses `confirmed | cancelled | completed | no_show`.
   - **Slots:** patients book a specific date within the next 14 days (today included), using the doctor's weekly availability as the template. Availability is stored as time ranges ("09:00 AM – 01:00 PM"); each range is split into bookable times by the doctor's **consultation duration** (`DoctorProfile.consultationDuration`, default 20 min, editable on Manage Availability). Only free future times are offered. Double-booking is prevented in the database: unique index on doctor + date + time for `confirmed` appointments.
   - **Cancellation:** the patient can cancel up to 2 hours before the start; the doctor can cancel any time while it is confirmed but must give a reason, which is sent to the patient. After the start time the doctor marks it `completed` or `no_show`.
   - **Prescriptions attach to an appointment** (one per appointment, written once the appointment has started and it isn't cancelled / no-show). The doctor's patient list comes from their appointments — no raw patientId input. On the patient side each prescribed test has a "Find labs" button that opens Book Tests filtered to that test.
   - **Lab bookings:** test + visit date (no time; within the next 14 days), auto-confirmed, paid at the lab or through one of the patient's active/completed installment plans for that test at that lab (a plan covers one booking). Statuses `confirmed → sample_collected → completed`, or `cancelled`. The patient can cancel before the visit date. The lab marks sample collected / completed; uploading a report for a booking links it and completes the booking (sample must be collected first).
8. **True Cost Analysis and Urdu text-to-speech (Step 4, decided 2026-10-03).**
   - **Lab location:** the lab drops a pin on an OpenStreetMap (Leaflet) map, or uses its current location, on Test Catalog; stored as coordinates on `LabProfile`. A warning shows until it's set.
   - **Patient location:** browser geolocation (or a dropped pin) when True Cost is switched on; used for the calculation only, never stored.
   - **Distance:** road distance + drive time from the public OSRM service (one table request for all labs, URL in `.env`); if OSRM fails, straight-line distance × 1.3, labelled approximate.
   - **Travel cost:** the patient picks how they travel — motorbike PKR 10/km, car PKR 35/km, rickshaw/ride-hailing PKR 55/km (defaults, changed from 8 / 25 / 50 on 2026-10-05, editable in `.env`); cost = km × 2 (round trip, one visit) × rate. True cost = test price + travel cost; labs sorted by true cost for a searched test, "Best value" badge; labs without a location listed last.
   - **Urdu text:** the installment agreement has a fixed Urdu template (team proofreads) filled with the same details and stored next to the English one (English stays binding). Report summaries: the lab writes a short English summary when uploading; **Azure Translator** translates it to Urdu; the lab can review and correct the Urdu. Urdu is shown right-to-left in a Nastaliq font.
   - **Urdu audio:** **Azure Speech**, voice ur-PK Uzma (female) by default with a toggle to Asad (male). The browser asks for a specific agreement / report; the server checks access, generates or reuses cached audio (private folder, not `/uploads`) and streams it — keys never reach the browser and no arbitrary text is accepted. Listen buttons: agreement (patient Apply page, My Wallet, lawyer case view) and report summaries (patient My Reports / Appointments, doctor Patient Reports).
   - Keys in `.env` (`AZURE_SPEECH_KEY/REGION`, `AZURE_TRANSLATOR_KEY/REGION`); without them translation is skipped and Listen explains audio isn't configured. The e2e test uses a local fake Azure server.

9. **Automatic lab report summary (decided 2026-10-04).** Reports are hard for patients to read and labs may not write a summary, so every uploaded report is read automatically and the summary goes **straight to the patient** (no review step), always telling them to share the report with their doctor and visit them.
   - **Reading:** Azure AI Document Intelligence (`prebuilt-layout`, free tier F0 — reads 2 pages per request and ~4 MB per file, so PDFs are sent in 2-page pieces, up to 12 pages per report; a photo over 4 MB is sent as a smaller JPEG copy (≤3000 px, made with `sharp`) — the stored original is untouched). Works on scans; OCR noise is cleaned up.
   - **Understanding without AI:** our own rules (`utils/reportInterpreter.js`) find result tables and compare each value only with the normal range **printed on the report** (or the lab's own High/Low flag): graded bands, sex-specific ranges (sex read from the report), word results (Nil / Negative / ++), count pairs. A stand-alone "Positive / Reactive / Detected" line outside a table is always flagged. Anything that can't be compared is shown as "ask your doctor", never as normal. Layouts handled (2026-10-05, IDC report): header printed as a separate table (columns then guessed from the cells, strictly left to right name → result → range), rows OCR merged into one cell (read as text: "name result range" or "name range result"), chart-style reports with the range under the name and the lab's "Normal" under the value, decimal commas, "number: label" bands (">60: Normal"). A lab's guidance table ("Optimal / Borderline High …") is never read as results.
   - **Summary:** fixed English + Urdu templates (no machine translation) listing what is outside the range; an all-normal result never claims the whole report is normal. **Written reports (histopathology, radiology) are not summarised** — the patient is told a doctor needs to explain it (we never read a diagnosis like "metastatic adenocarcinoma" aloud automatically).
   - The patient sees the flagged results, the summary with Urdu Listen, a "see your doctor" box with **Book a doctor**, and "created automatically — check the original report". A lab-written summary always wins; the lab can still edit, and can **Read again** a failed report.
   - Sample reports for development live in `lab-reports/` (gitignored — real patient data).

10. **CNIC pictures with installment applications (decided 2026-10-04).** An unverified CNIC no longer blocks an installment plan.
   - **Apply:** the patient uploads pictures of the **front and back** of their own CNIC and the guarantor's (JPG/PNG, 10 MB each) — every application, no reuse — and gives both home addresses (own address prefilled from the profile). The agreement names both addresses and the patient confirms the pictures are theirs and the guarantor's.
   - **Admin review:** the admin compares the pictures with the CNIC numbers, names and addresses before approving. **Approving the plan also verifies the patient's CNIC** (community support unlocks too); rejecting leaves the CNIC status as it was. A CNIC the admin already **rejected** must be corrected on the Profile page before applying, and the CNIC can't be changed while an application is under review.
   - **Default:** the lawyer assigned to the defaulter case sees the agreement and all four pictures; the generated legal notice includes the patient's CNIC and address and says the pictures are attached.
   - **Privacy:** pictures are stored outside `uploads/` and served only through `/api/documents` to the patient, admins and the assigned lawyer.

11. **Slips and in-app dialogs (decided 2026-10-04).**
   - **PDF slips** (downloaded from the dashboards, made by the server): appointment slip (date/time, doctor, clinic name + address, fee paid at the clinic, patient + CNIC), lab visit slip (test, lab + address, visit date, price / paid through an installment plan), and **community support slip** for an approved application (patient in need with CNIC + address, test, assigned lab, approval date) followed by the **documents the patient uploaded**. Cancelled bookings have no slip.
   - **Checking a slip:** every slip carries a unique number (`AP-`/`LB-`/`CS-XXXX-XXXX`). The lab or doctor checks it against their dashboard (slip number on each booking + a "Check a slip number" box); no public verification page, so nothing about the patient is exposed.
   - Doctors have an optional **clinic name and address** (Profile), shown in Find Doctors and printed on the slip.
   - All browser `confirm` / `alert` popups in the dashboards were replaced with in-app dialogs (`components/Dialog.tsx`).

12. **Labs with several branches — Option B (decided 2026-10-05).** One CareFirst account per lab chain, with its branches inside it.
   - **Branches:** name, address, area, phone, opening hours and a map pin each; managed on the lab's Branches page. Every lab has at least one (registration creates it; older labs got one at startup). Payment details, tests and prices stay per chain.
   - **Tests:** offered at every branch by default; the lab can limit a test to some branches.
   - **Booking:** the patient picks the branch they will visit (sorted by distance when True Cost is on; chosen automatically when only one branch offers the test). The slip shows the branch, its address, phone and hours. True Cost uses the nearest branch that offers the test.
   - **Wrong branch:** the patient can change the branch until the sample is collected; a lab's other branch can find the slip and **take the visit** ("Take visit here") if it offers the test. Either way the other side is notified and the move is recorded on the booking.
   - **Faisalabad dataset:** 5 chains (Chughtai, IDC, Citilab, Excel, Innova) with their branches, regular prices and approximate pins, plus 28 doctors, prepared in `dataset/` and loaded with `npm run import:dataset`. Lab payment details are demo values; doctors keep their real names, with fee / duration / timings filled in by specialty and shown like any other doctor's (not marked as demo). Online-only doctors and non-doctors are left out.

13. **Patients choose which doctors see their reports (decided 2026-10-05).**
   - A doctor sees a lab report only after the patient shares it with them — prescribing the test no longer gives access (applies to Patient Reports and the Urdu audio).
   - The patient can share with doctors they visited or booked: a `completed` or `confirmed` appointment (cancelled / no-show don't count). Report by report, doctor by doctor.
   - The doctor is notified when a report is shared; the patient can stop sharing any time and the doctor loses access at once.

14. **Defaulters are restricted until they pay (decided 2026-10-06).**
   - When a plan becomes `defaulter`, the patient's account is restricted: only **My Wallet** (to pay), Notifications, Profile, My Reports / prescriptions and their existing appointments + lab visits (kept, can be cancelled) stay open. Booking doctors or lab visits, applying for installment plans and community support are blocked in the app and the API.
   - The patient pays the lab and uploads receipts for the **overdue** installments through the usual chain (patient → lab → admin). When the admin verifies the last overdue one, the plan returns to `active` (or `completed`), the case closes as **paid** and the patient, lawyer and admins are notified. The remaining installments continue on their dates.
   - The lawyer can also **close a case** settled outside CareFirst (a note is required): the overdue installments are recorded as settled and the account returns to normal.
   - **Receipt rejection:** the lab (before confirming) or the admin (before verifying) can reject a down-payment / installment receipt with a reason; it is cleared and the patient uploads a new one (the lab is told when the admin rejects).
   - The admin sees a **Defaulters** list with CNIC and e-mail (Restricted / Cleared) and a Defaulter tag in Manage Users.
